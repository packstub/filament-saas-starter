# Filament SaaS Starter

A multi-tenant SaaS on Laravel 13 and Filament 5, created from the starter kit `packstub/filament-saas-starter`: sign-up with e-mail verification and two-factor authentication, workspaces on Filament's single-database tenancy, members and invitations (Filament Teams), plans and limits (Filament Features), Stripe billing (Laravel Cashier) and support logins (Filament Account Switcher). The code is meant to be read and changed: clear names, no leftovers, comments only where the reason is not obvious. `README.md` is the tour.

## Commands

```bash
composer setup              # install, .env, key, SQLite, migrate --seed, npm install, npm run build
composer test               # Pint (check) and the Pest suite
composer lint               # Pint
php artisan migrate:fresh --seed
```

## Layout

- `app/Providers/Filament/AppPanelProvider.php`: the customer panel at `/app/{workspace}` (default panel, registered last in `bootstrap/providers.php`), two-factor authentication optional; `AdminPanelProvider.php`: the back office at `/admin`, `is_admin` only, two-factor authentication required outside the local environment.
- `app/Filament/Plugins.php`: the optional plugins of each panel (`app()`, `admin()`), empty in the kit; a module recipe in `docs/modules` adds its plugin there, never to the providers. `PluginsTest` checks each one is registered.
- `app/Providers/AppServiceProvider.php`: the morph map, `Model::shouldBeStrict()` outside production, `Password::defaults()`.
- `app/Models`: `Workspace` (the tenant, the Cashier billable, `named()`, `reservedSlugs()`, `changePlan()`, `currentSubscription()`, `trialDaysOnOffer()`, `syncPlanFromSubscription()`, the `deleting` hook), `User` (panel access, `canInWorkspace()`, `deleteAccount()` and `workspacesBlockingDeletion()`, impersonation rules, app authentication), `Project` (the example resource, ULID key), `AuditEvent` (the workspaces' audit log: `record()`, `description()`, pruned after `audit.retention_days`); `app/Enums/ProjectStatus.php`, `AuditEventType.php`.
- `app/Support/DataExport.php`: the personal and the workspace data exports (streamed JSON), downloaded from `/exports/me` and `/exports/workspaces/{slug}` (`routes/web.php`, the two invokable controllers in `app/Http/Controllers`; never return a download from a Filament action, Livewire buffers it whole); a new workspace table is added to `forWorkspace()` as well as to the `deleting` hook.
- `app/Actions/CreateProject.php`: a project created within the plan's limit, under a lock per workspace; the panel goes through it, and any new way of creating projects should too.
- `app/Support/Plans.php` and `SupportLogins.php`: the Features and Account Switcher plugins, one definition used by both panels; `WorkspacePermissions.php`: a member's permissions remembered for one request (behind `User::canInWorkspace()`), emptied by `app/Listeners/ForgetWorkspacePermissions.php` on every Teams membership event.
- `app/Billing/StripePrices.php` + `config/billing.php`: plan key and interval (`monthly`, `yearly`) to Stripe price and amount, and back; `app/Listeners/SyncWorkspacePlanFromStripe.php`: Cashier's `WebhookHandled` to the workspace's plan, and `customer.deleted` on `WebhookReceived` back to the default plan; `RecordWorkspaceActivity.php`: Teams' membership events into the audit log (plan changes and deletion are recorded by `Workspace`); `RefuseUnsignedStripeWebhooks.php`: no webhooks in production without the signing secret; `UpdateStripeBillingContact.php`: the Stripe customer's e-mail follows a Transfer ownership (queues `app/Jobs/SyncStripeCustomer`); `SyncSeatQuantityWithStripe.php`: a per-seat plan's subscription quantity follows the members (queues `app/Jobs/SyncSeatQuantity`) (`Workspace::syncSeatQuantity()`, `per_seat` in `config/billing.php`, off by default).
- `app/Billing/RevenueMetrics.php`: the admin dashboard's figures (MRR from `unit_amount` in `config/billing.php`, subscriptions, trials, churn, sign-ups, plans, plan changes), from the app's own tables, cached for five minutes, never from Stripe; the widgets are in `app/Filament/Admin/Widgets`.
- `app/Filament/App`: `Pages/Activity` (the audit log, owners and admins), `Pages/Auth/EditProfile` (Filament's profile page plus Connected accounts, Download your data and Delete account), `Pages/ApiTokens` (owners and admins), `Pages/Billing`, `Pages/Tenancy/*` (`EditWorkspace` also holds Export workspace data and Delete workspace, owners only), `Resources/Projects`, `Widgets/GettingStarted` (the onboarding checklist, steps from real data, dismissed per workspace) and `Widgets/WorkspaceOverview`; `app/Filament/Admin`: Users (with Impersonate), Workspaces (with Change plan and a link to its Activity) and AuditEvents (Activity: every workspace's audit log, read-only).
- The public site: `routes/web.php` (home, `/terms`, `/privacy`, `/sitemap.xml`, `/robots.txt`), `app/Http/Controllers/HomeController.php`, `resources/views/site` and `resources/views/components/site` (layout with the meta tags, legal frame), `app/Support/Pricing.php` (the pricing section from the plans and `config/billing.php`, also what the Billing page lists per plan), `config/site.php` (tagline, description, company, contact address).
- The API: `routes/api.php` (`/api/v1`, `auth:sanctum`, the `api_access` plan feature, `abilities:…` per route, the `api` rate limiter in `AppServiceProvider`), `app/Http/Controllers/Api/V1`, `app/Http/Resources`, `app/Http/Requests`; tokens are Sanctum tokens owned by the `Workspace` (`App\Models\ApiToken`, abilities in `ApiToken::ABILITIES`), revoked when their creator stops being an owner or admin (`app/Listeners/RevokeApiTokensOfFormerManagers.php`), managed on `app/Filament/App/Pages/ApiTokens.php`. A request authenticates as the workspace: start every query from `$request->user()`.
- Social sign-in: `app/Support/SocialLogin.php` (providers on when `services.<provider>` has credentials), `app/Http/Controllers/Auth/Social*Controller.php` (links only verified addresses on both sides, never skips two-factor authentication or signs in an admin), `App\Models\SocialAccount`, the buttons in `resources/views/filament/app/social-login.blade.php` (render hooks in `AppPanelProvider`), Connected accounts on `EditProfile`. `users.password` is nullable: check `User::hasPassword()`, and keep `signInMethodCount()` above zero.
- `docs/modules`: recipes for optional packages (one file each, the index in its `README.md`). In the kit's own repository (not in a project made from it), their annotated code blocks are what `scripts/verify-module.sh <name>` applies to a copy of the kit before running the suite (`scripts/apply-recipe.php` lists the directives); maintainers run it after changing a recipe. `scripts/` and `.github/workflows/modules.yml` are maintainer files, left out of a new project; in a project made from the kit, follow a recipe by hand.
- `docs/deploy`: the Laravel Cloud and server guides, `environment.md` (every variable `.env` may hold; `EnvironmentReferenceTest` keeps it in step with `.env.example` and `config/`) and the production checklist.
- `config/packstub-features.php`: features and plans; `config/packstub-teams.php`: roles, the `workspace_user` pivot.
- `database/seeders/DatabaseSeeder.php`: the demo accounts, idempotent, skipped in production; its e-mail constants are the developer logins.
- `tests/Feature`: sign-up, authentication, workspaces, invitations, the project limit and access by role, billing webhooks, the Billing page and per-seat billing, support logins and the admin tables, the seeder, the schedule; `tests/Unit/ArchTest.php`: architecture tests. Helpers in `tests/Pest.php`: `workspace()`, `memberOf()`, `admin()`, `inWorkspace()`, `inAdminPanel()`, `stripeSubscriptionEvent()`, `stripeSubscription()`, `fakeStripe()` (calls in `->requests`, their parameters in `->params`), `countQueries()`, `appTables()`, `rowsLeftOf($workspace)` (rows in any table that still name a workspace: empty after `$workspace->delete()`, the audit log aside).

## Conventions

- PHP 8.3+, Pint, Pest. Every change comes with a test; `composer test` passes before finishing.
- Tests: datasets instead of loops, `expect(fn () => …)->toThrow()` or an assertion on the outcome instead of `try`/`catch`, factory states (`admin()`, `withAppAuthentication()`, `unverified()`, `paused()`, `onPlan()`) instead of mocked models, `fakeStripe()` for the calls to Stripe. A test user signed in to `/admin` needs `admin()`: the panel requires two-factor authentication.
- Models are strict outside production: eager-load what a table or a policy reads (`getEloquentQuery()`), and give `UserFactory` a value for every new `users` column (`actingAs()` users are never re-read from the database).
- Both panels use the same `Plans::plugin()`, and `AppPanelProvider` stays last in `bootstrap/providers.php`: console commands, queued jobs and webhooks run with the settings of the panel registered last.
- The migrations in `database/migrations` are the published ones of each package, renamed only in their date prefix; Cashier's point at `workspaces` and `workspace_id`.
- What a workspace owns has its migration in `database/migrations/workspace`: a ULID key, an indexed `workspace_id`, no database foreign keys to `workspaces` or `users`, rows removed in `Workspace`'s `deleting` hook (which also removes its Cashier subscriptions and feature overrides) or, for a module's tables, in a synchronous listener of `App\Events\WorkspaceDeleting`, which the hook dispatches first inside the transaction, before the Stripe cancel and the kit's own rows (rows only in there; files and other services in `DB::afterCommit()`) (`DeletionEventsTest` refuses a queued one); `App\Events\AccountDeleting` is the same for `User::deleteAccount()`. `TableRulesTest` enforces the table rules: every table is either in its `centralTables()` list, with a reason, or a workspace's own table that follows them. `Workspace::delete()` wraps the hook and the row in one transaction, so delete a workspace through the model (`$workspace->delete()`), never with a query (`Workspace::where(…)->delete()` skips both). A subscription Stripe no longer has (`resource_missing`) does not stop the delete; any other Stripe error does. That keeps a later move to a database per workspace (Filament Tenancy) mechanical.
- `config/packstub-teams.php` and `config/packstub-features.php` name their `connection` (`DB_CONNECTION`) instead of leaving it null, so their tables stay on the app's own database if workspaces ever get databases of their own.
- App code reads memberships through the `Teams` facade (`Teams::ownersOf()`, `membersOf()`, `teamsOf()`), not through the traits' relations, and never queries a workspace's own tables from the admin panel. The one exception is the counts of the admin tables, which need a relation name: `withCount('members')` and `withCount('joinedTeams')`.
- The audit log (`audit_events`) is central on purpose, like billing and `account_switches`: a ULID key, `workspace_id` and names kept as they were, no foreign keys. Record new kinds of events through `AuditEvent::record()`; never edit an entry.
- Never queue a listener of Filament Teams' events: they carry whole `User` models without `SerializesModels`, so the queue would store password hashes and remember tokens. Listen synchronously and dispatch a job that holds the workspace (its id) instead; `QueuedJobsTest` checks the stored payloads.

## Guidelines and Laravel Boost

The rules above, with the how-tos, are in `.ai/guidelines` (architecture, workspace data, billing, testing, extending, never do this) and the skill `.ai/skills/adding-a-workspace-resource`. Read the guideline for the area you change before planning. `AgentGuidelinesTest` checks that every file and class they name exists.

Laravel Boost is a dev dependency: `php artisan boost:install` adds its MCP server (database schema, queries, logs, the Laravel docs search) and copies those guidelines and skills, with Laravel's own, into each coding agent's files. It keeps what is written outside its `<laravel-boost-guidelines>` block of this file. Re-run `php artisan boost:update` after `composer update`, and edit `.ai/`, never the generated copies.
